# Eval budget and CI gate policy

## `--validate` / report runs

- The command `python evals/runner.py --validate` lints every eval spec (JSON parses, `skill_name` matches the directory, required fields and referenced scripts/fixtures exist). It runs **in CI** and **never touches the network**; no model calls, no LLM judge, no captured runs. **No token or time cap is needed** for this command.

## Label‑gated and nightly model‑graded runs

- Any `run-evals` or nightly run that invokes a model (LLM judge or otherwise) **must** have an explicit token and wall‑time cap configured in the workflow file.
- The cap is set by the maintainer; the workflow must not exceed it.
- If the cap would be exceeded, the job is cancelled and the failure is reported as an advisory, not a blocking gate.

## LLM judge

- The optional LLM judge (`EVAL_JUDGE_CMD`) is **never** required, never bundled, and **never runs in CI**. It may be enabled locally for ad‑hoc debugging only.

## Eval‑maintainer agent contract

- The agent may **only** invoke `python evals/runner.py --validate`, list suites, detect missing captures, and generate plain‑language reports from `evals/runs/`.
- The agent **must not** launch captures, run model‑graded assertions, or execute any command that contacts a model or agent harness.
- All reports generated by the agent must include the exact commands run and their output; missing or malformed metadata does not make an otherwise gradeable capture fail, but must be reported accurately.
